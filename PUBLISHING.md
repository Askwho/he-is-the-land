# Publishing the "He Is The Land" player site

This folder is a [Quartz v5](https://quartz.jzhao.xyz) site that publishes selected
notes from the Obsidian vault to **https://heistheland.askwhocasts.com** (a Cloudflare
Worker on your askwhocasts.com zone). A copy is also pushed to GitHub
(askwho.github.io/he-is-the-land) as a backup.

The repo is **public**, so the Markdown of any published note is readable on GitHub —
but only notes you explicitly mark are ever copied here. Your DM vault stays private.

## The one command

```powershell
cd "C:\Users\askew\Documents\DnD\Barovia\PlayerSite"
.\publish.ps1                                  # sync + build only (safe preview)
.\publish.ps1 -Push -Message "Add Session 6"   # go live (GitHub + Cloudflare)
.\publish.ps1 -UploadAudio -Push               # also upload new podcast MP3s to R2
```

Preview locally before going live: `npx quartz build --serve` → http://localhost:8080

## What gets published (three sources)

1. **Vault notes with `publish: true`** in their frontmatter — synced into `content\`
   with `%% DM-only comments %%` stripped. Everything else in the vault is ignored.
2. **Images in the vault folder `z_Assets\Player Site\`** — the whole folder is
   published verbatim. ONLY put player-safe images there. Reference them from notes
   with a normal Obsidian embed: `![[granny.webp|300]]`.
3. **`content\index.md`** — the site home page. Site-native; edit it here directly.
   It is the only file in `content\` that survives a sync — everything else is
   regenerated from the vault, so never hand-edit other files in `content\`.

## The player-facing vault folders

- `1-Session Journals\` — `Session_XXX_Player_Recap.md` + `Session_XXX_Player_Notes.md`
  (publish: true) and your private `Session_XXX_DM_Notes.md` (no flag, never synced).
  Also `The Story So Far.md` — extend it with a chapter per session.
- `1-Player Compendium\` — Cast, Places, Quests & Threads, Traveller's Almanac,
  Handouts. **Spoiler rule: only facts the players learned at the table.** Update
  after each session (the Quests watch-list and Cast pages age fastest).
- `1-Podcast\` — one page per episode + the podcast landing page.
- `1-Party\Player Handouts\The Party (Player Reference).md` — keep "as of Session N"
  current.

## Publishing a new podcast episode (after Session N)

1. Build the episode as usual → MP3 lands in `Sessions\Podcast\out\`.
2. Add the episode to `episodes.json` (bytes, duration, date, description, page slug —
   copy an existing entry; get duration/chapters via
   `ffprobe -v quiet -print_format json -show_chapters -show_format <mp3>`).
3. Create `1-Podcast\Episode N — Title.md` in the vault (copy an existing episode page)
   and drop its cover into `z_Assets\Player Site\cover-s0N.jpg`.
4. Run `.\publish.ps1 -UploadAudio -Push`. Subscribers' apps pick it up from the feed
   automatically.

The feed is `https://heistheland.askwhocasts.com/podcast/feed.xml`, generated by
`scripts\generate-feed.mjs` from `episodes.json` on every build.

**Dark mode is the default** (visitors' own toggle choice still wins). This is
applied by `scripts\patch-theme-default.mjs` after the Quartz build — so always
publish via `publish.ps1`, not a bare `npx quartz build` + `wrangler deploy`,
or the site reverts to following the visitor's OS theme.

## How the hosting works

- **Worker `he-is-the-land`** serves the built site as static assets on the custom
  domain `heistheland.askwhocasts.com` (config in `wrangler.jsonc`).
- **Podcast audio** lives in the R2 bucket `he-is-the-land-media` (free egress).
  The worker streams it at `/audio/<file>` with HTTP Range support (`worker\index.js`),
  which podcast apps require.
- **`/upload/<file>`** (PUT) adds audio to R2. It's protected by a bearer token: the
  worker secret `UPLOAD_TOKEN`, mirrored locally in the git-ignored `.upload-token`
  file, which `publish.ps1 -UploadAudio` reads. If the token is ever lost, generate a
  new one into `.upload-token` and run:
  `npx wrangler secret bulk` with `{"UPLOAD_TOKEN":"<new>"}`.
- Deploys use the wrangler OAuth login on this machine (`npx wrangler whoami`).

## Two layers of spoiler protection

1. **`publish.ps1`** only copies notes marked `publish: true`, and strips `%% ... %%`
   comments before copying — so DM text never reaches this folder or GitHub.
2. **Quartz's `explicit-publish` plugin** is enabled, so even if an unmarked note
   landed in `content/`, it would not be rendered.

And the golden rule for the compendium: **if the players haven't heard it at the
table, it doesn't go on a page** — book names included (e.g. the road is "The Road
West" until someone in-world names it).
